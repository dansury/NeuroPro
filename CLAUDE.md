# NeuroPro — Claude Code Guide

Сервис психофизиологической интерпретации тестов оборудования **«Эгоскоп»**.
Загружает Excel‑выгрузку теста + скриншот таблицы «смысло‑эмоциональной
значимости», строит **математическую** диаграмму‑паутинку (когнитивные
показатели ⊕ физиология), и выдаёт брендированную интерпретацию (PDF / e‑mail)
через выбранную нейросеть.

> Эта работа ведётся по двум методологиям: **Spec Kit** (spec‑driven
> development) и **BMAD‑METHOD** (agentic agile). Раздел «Рабочий процесс» ниже —
> обязателен к соблюдению.

---

## Рабочий процесс (Spec Kit + BMAD)

Мы совмещаем две методологии. Правило выбора простое:

| Задача | Инструмент | Команда / скилл |
| --- | --- | --- |
| Новая крупная фича «с нуля», нужен анализ → PRD → архитектура → истории | **BMAD** | `bmad-agent-analyst` → `bmad-create-prd` → `bmad-create-architecture` → `bmad-create-epics-and-stories` |
| Формализовать одну фичу в исполнимую спецификацию и план | **Spec Kit** | `/speckit-specify` → `/speckit-clarify` → `/speckit-plan` → `/speckit-tasks` → `/speckit-implement` |
| Реализация конкретной истории/таска | **BMAD** | `bmad-dev-story` / `bmad-quick-dev` |
| Ревью, edge‑cases, ретро | **BMAD** | `bmad-code-review`, `bmad-review-edge-case-hunter`, `bmad-retrospective` |
| Проверка согласованности артефактов спеки | **Spec Kit** | `/speckit-analyze`, `/speckit-checklist` |

**Базовый цикл для любой новой работы:**

1. **Spec first.** Не пишем код без спецификации. Для фичи запусти
   `/speckit-specify`, описав *что* и *зачем* (без деталей реализации). Спека
   ложится в `specs/NNN-<slug>/spec.md`.
2. **Уточнение.** `/speckit-clarify` снимает неоднозначности до планирования.
3. **План.** `/speckit-plan` — технический план под Конституцию проекта
   (`.specify/memory/constitution.md`). План — в `specs/NNN-*/plan.md`.
4. **Задачи.** `/speckit-tasks` раскладывает план в `tasks.md`.
5. **Реализация.** Веди разработку как BMAD‑истории (`bmad-dev-story`):
   маленькие вертикальные срезы, каждый — рабочий и проверяемый.
6. **Качество.** Перед PR — `bmad-code-review` + `/speckit-analyze`.

Артефакты живут в репозитории и версионируются вместе с кодом:

- `.specify/` — движок Spec Kit (шаблоны, скрипты, конституция).
- `specs/NNN-*/` — спеки, планы, задачи по фичам.
- `_bmad/` — модули BMAD (core, bmm) и их воркфлоу.
- `.claude/skills/` — установленные скиллы обеих методологий (`speckit-*`,
  `bmad-*`).

Текущая фича уже описана: `specs/001-neuropro-service/`.

## Конституция проекта

Принципы — в `.specify/memory/constitution.md`. Ключевое, что проверяется в
ревью каждой задачи:

1. **Диаграмма, матрица и все показатели — математика, не нейросеть.** Геометрия
   диаграммы — `www/lib/chart.php`, матрицы — `www/lib/matrix.php`, а уровни
   выраженности, положение относительно медианы, достоверность, соотношение шкал
   между собой, разделы отчёта и итоги методики — `www/lib/metrics.php`.
   Нейросети используются **только** для текстовой интерпретации и OCR: модель получает
   готовый расчёт и не имеет права его пересчитывать, переклассифицировать или
   противоречить знаку «Знач.».
2. **Никаких выдуманных данных.** Числа берутся из Excel и OCR; если данных нет —
   честно отмечаем прочерком (это же требование зашито в промпты).
3. **Чистый PHP, без Composer.** Только `ext-curl`, `ext-gd`, `ext-pdo_sqlite`,
   `ext-zip`, `ext-mbstring`. Переиспользуем библиотеку из `www/lib/`.
4. **Секреты — только через ENV / `.env` / `setup.php`.** В коде секретов нет.
   На хостинге, где нельзя положить файл над веб-корнем, всё (включая пароль
   администратора) задаётся через `setup.php`: значения хранятся в таблице
   `settings` (БД в `data/` над веб-корнем) и переживают деплой. Пароль
   администратора задаётся при **первом запуске** прямо в `setup.php` — править
   перезаписываемый `config.php` или загружать `.env` не нужно.
5. **Версионируемость промптов и интерпретаций.** Любая интерпретация привязана к
   конкретной версии промпта; история не теряется.

## Архитектура

> **Деплой:** прод обновляется через `https://<host>/pull.php`, который зеркалит
> в веб-корень хостинга **только** содержимое `www/` (см. `pull-config.php`,
> `subdir = /www`). Поэтому библиотека живёт в `www/lib/` — внутри деплоящегося
> веб-корня. Каталог данных и `.env` живут **над** веб-корнем
> (`cfg_data_root()` / `cfg_load_env_file()` в `config.php`): локально это
> `data/` и `.env` в корне репозитория.

```
www/                  # ← веб-корень; ровно это зеркалится на прод через pull.php
  lib/
    config.php        # .env + ENV + overlay настроек из таблицы settings
                      #   AVAILABLE_MODELS — общий каталог моделей (Yandex AI Studio
                      #   + OpenRouter), сгруппированный по `group` для UI
    db.php            # SQLite-схема: profiles, prompts, prompt_versions, interpretations
    excel.php         # Чтение .xls (OLE2+BIFF8) / .xlsx / .csv — чистый PHP
    profile.php       # Грид Excel → структурный профиль (метаданные, баллы шкал, тип теста: СМУ/ИЖС/Басса-Дарки)
    metrics.php       # ДЕТЕРМИНИРОВАННЫЙ расчёт всех показателей и их соотношений:
                      #   уровень (% от максимума СВОЕЙ шкалы), ранг в профиле,
                      #   положение относительно медианы (по знаку «Знач.»),
                      #   достоверность, раздел отчёта, итоги методики для ЛЮБОГО
                      #   теста (totals: суммы СМУ, напряжённость защит ИЖС, индексы
                      #   Басса-Дарки) и координаты матрицы. Нейросеть НЕ считает.
                      #   Разделы: «скрытое напряжение» — ТОЛЬКО ниже нижнего порога
                      #   по ответам (у СМУ раздел зовётся «Антимотиваторы», см.
                      #   CATEGORY_BY_TEST); из отчёта выпадает лишь то, что ниже
                      #   ОБОИХ порогов — и по тесту, и по полосе медианы.
                      #   У Басса-Дарки семь общих категорий сливаются в ЧЕТЫРЕ
                      #   группы видов агрессии по положению на матрице
                      #   (CATEGORY_MERGE_BY_TEST + CATEGORY_ORDER_BY_TEST):
                      #   «Проявленные» (справа и сверху; в промпт уходит разбор
                      #   ведущего канала СМК), «Проявленные без телесного
                      #   напряжения» (справа, тела нет), «Скрытое напряжение»
                      #   (слева сверху) и «Не проявляются» — они не выпадают из
                      #   отчёта, а печатаются списком без разбора (listsSkipped()).
                      #   SCALE_MEANING — канонические описания шкал методики
                      #   (виды агрессии): определения тоже не сочиняет нейросеть.
                      #   SMK_MEANING_BY_TEST — тот же канал X/Y/Z в терминах
                      #   методики (у Басса-Дарки Z — решительно и без паузы,
                      #   Y — сильные переживания во время или после, X — с холодной
                      #   головой).
                      #   firstStep() — ОПОРА ПЕРВОГО ШАГА: шкала, вокруг которой
                      #   строится единственное действие в конце отчёта («с чего
                      #   начать»). Сначала шкалы с телесным откликом выше медианы
                      #   (p<0.01 раньше p<0.05), внутри тира — по весу показателя;
                      #   если отклика выше медианы нет ни у одной шкалы, опорой
                      #   становится самая нагруженная шкала отчёта, и основание
                      #   честно об этом говорит. Выбор — математика, не нейросеть
                      #   Пороги уровней и контраст размеров кружков — настройка
                      #   оператора (Metrics::configure() из np_boot); withConf()
                      #   считает по сохранённому снимку настроек
    chart.php         # МАТЕМАТИЧЕСКАЯ радар-диаграмма (SVG): единая процентная шкала —
                      #   когниция (% от максимума шкалы) ⊕ физиология («Знач.», медиана
                      #   на кольце 50 %, p<0.05 — жирная точка И жирная подпись оси).
                      #   Под подписью каждой оси — результат теста по этой шкале
                      #   (для ЛЮБОЙ методики, не только ИЖС).
                      #   При наведении на оранжевую точку физиологии она укрупняется
                      #   (CSS :hover в самом SVG, без JS) и красится секторами СМК —
                      #   теми же цветами и той же геометрией, что и кружок на матрице
                      #   (Matrix::sectorPaths(), публичный — общий источник цвета).
                      #   Легенда и подписи подстраиваются под размер картинки; у
                      #   легенды своя полоса высоты под картинкой (не делит место с
                      #   диаграммой), иначе на уменьшенных картинках подпись нижней
                      #   оси наезжала на первую строку легенды
    matrix.php        # МАТЕМАТИЧЕСКАЯ матрица «когниция × эмоция» (SVG): ось ординат
                      #   (вертикальная) — результаты теста в единицах теста (выше —
                      #   результат сильнее), ось абсцисс (горизонтальная) — телесный
                      #   отклик, «Знач.» (медиана по центру, правее — отклик сильнее);
                      #   бледный пунктир — пороги (по умолчанию 40/60 %, теперь
                      #   горизонтальные линии) и полоса медианы (вертикальные линии).
                      #   Вид кружка задаёт ОДНА таблица bubbleStyle():
                      #   выше медианы — секторы СМК (Y оранжевый, X синий,
                      #   Z зелёный; параметра нет в токене — нет и сектора),
                      #   ниже медианы — ОДИН преобладающий цвет без разбивки,
                      #   СМК не распознан — фиолетовый, ответы ниже порога при
                      #   отклике тела — красная обводка, ниже обоих порогов —
                      #   бледно-серый. Размер — сумма когнитивного и эмоционального
                      #   ответа, нормированная по разбросу профиля: настройка
                      #   меняет РАЗНИЦУ между кружками, а не их размер.
                      #   Наложившиеся кружки разводит spread(). Жирная тёмная
                      #   обводка — p<0.05.
                      #   На странице результата пунктир ТАЩИТСЯ мышью: кружки
                      #   перекрашиваются на лету (JS зеркалит те же таблицы),
                      #   значения сохраняются в settings, после чего страница сама
                      #   перезагружается (500 мс дебаунс) — раздел отчёта в таблице
                      #   расчёта пересчитывается по новым порогам без лишнего клика.
                      #   В отчёте клиента матрица стоит ВМЕСТО таблиц
    phys.php          # Разбор OCR-текста таблицы значимости → «Знач.» + p + СМК (X/Y/Z)
                      #   по осям. Из ЧИСЕЛ читается только «Знач.»: «Балл», «m» и
                      #   прочие столбцы скриншота игнорируются (баллы — из Excel)
    ocr (в llm.php)   # LLM::ocrImage() — Yandex Vision OCR скриншота
    llm.php           # Провайдеры Yandex (по умолчанию) + OpenRouter, fallback, OCR
                      #   Цепочка: выбранная модель у каждого провайдера
                      #   (LLM_PROVIDER_PRIORITY), затем LLM_FALLBACK_MODELS.
                      #   Слаг модели никогда не уходит чужому провайдеру.
                      #   LLM::recognizeSignificance() режет скриншот таблицы значимости
                      #   на горизонтальные полосы по строкам (ext-gd, sliceSignificanceImage,
                      #   ≤6 строк на кусок + небольшой нахлёст) и слегка увеличивает
                      #   каждую перед распознаванием: то же изображение, но на строку
                      #   приходится больше эффективных пикселей — таблицы с 8-12 мелкими
                      #   строками (СМУ/Басса-Дарки/ИЖС) читаются заметно точнее. Резать
                      #   не удалось (нет ext-gd, странный формат) — падает обратно на
                      #   распознавание целиком, как раньше. Phys::fromVision() сшивает
                      #   строки кусков со шкалами по ключевому слову, а не по позиции
                      #   в массиве, поэтому границы кусков ничего не путают
    prompts.php       # Семейства промптов + версии (правила удаления/активации)
    prompts/          # Тексты автосидируемых версий промптов: *_v1.php (исходные,
                      #   вшиты в www/ чтобы деплоиться), *_v2.php (под недорогие модели),
                      #   *_v3.php (расчёт приходит готовым из metrics.php),
                      #   *_v4.php (+ итоги методики и зоны матрицы, таблиц в отчёте нет),
                      #   *_v5.php (глубина через объём — давала повторы),
                      #   *_v6.php (содержательность вместо многословности,
                      #   запрет повторов, разделы названы по методике),
                      #   bd_v7.php (описания видов агрессии + четыре
                      #   группы по матрице, непроявленные — списком),
                      #   bd_v8.php (та же математика, но язык клиента вместо
                      #   служебных обозначений — «СМК», «канал», X/Y/Z, названия
                      #   датчиков, «медиана», «порог» в тексте запрещены, смысл
                      #   передаётся поведением; запрет повторов усилен — нельзя
                      #   повторять и схему абзаца),
                      #   bd_v9.php (у Басса-Дарки: в «Скрытом напряжении»
                      #   два обязательных вывода — сейчас условий для проявления
                      #   нет, но телесная готовность осталась, и если жизненная
                      #   ситуация расшатается, есть риск вернуться к этим формам),
                      #   *_action.php (поколение «Первый шаг»: всё поколение «Sonnet»
                  #   плюс ПОСЛЕДНИЙ раздел «С чего начать» — ровно одно конкретное
                  #   действие, выполнимое клиентом на этой неделе, на шкале, которую
                  #   выбрал расчёт (Metrics::firstStep). Почему выбрана эта шкала,
                  #   клиенту не объясняется; потолок объёма поднят ровно на новый раздел),
                  #   *_action_v2.php (АКТИВНЫ У ВСЕХ МЕТОДИК — разбор реального
                  #   отчёта показал три проблемы поколения «Первый шаг»: там, где
                  #   хватало одного предложения на ~30 слов, модель писала два-три;
                  #   отчёт заканчивался «Коротким резюме», а не действием (резюме
                  #   убрано совсем — конец отчёта строго «С чего начать»); общий
                  #   показатель методики стоял в конце разбора шкал, а не открывал
                  #   его. v2 переставляет его сразу после «Как читать картинки» и
                  #   убирает «как часто»/«раз в неделю» из формата действия —
                  #   периодичность не выдумывается. Математика и состав разделов не
                  #   меняются; прежний *_action.php не правится — история версий
                  #   переживает правки следующих поколений (как и v7/v8/v9)),
                  #   *_sonnet.php (поколение помечено
                      #   не номером, а словом «Sonnet»: отчёт ВДВОЕ КОРОЧЕ при той
                      #   же математике. Один абзац на шкалу вместо двух, «Как
                      #   читать картинки» одним предложением, три рекомендации
                      #   вместо пяти, сжатые итоги и резюме, потолок объёма в
                      #   словах и короткий образец плотности — длинный пример сам
                      #   учил писать длинно. Ни одно требование прежних версий не
                      #   снято: те же разделы, запреты и все шкалы в отчёте),
                      #   style_v1.php (ВТОРОЙ СЛОЙ: литературная правка готового
                      #   отчёта — язык и краткость; факты и разделы не трогает),
                      #   style_sonnet.php (АКТИВНАЯ версия второго слоя: правка на
                      #   СЖАТИЕ — текст обязан стать короче, но не меньше двух
                      #   третей исходного, иначе interpret.php сочтёт это потерей
                      #   текста; состав шкал и разделов неприкосновенен)
    interpret.php     # Интерпретация в ДВА СЛОЯ + сохранение результата.
                      #   Слой 1 — содержание: в промпт уходят расчёт, итоги,
                      #   описание матрицы и опора первого шага (для ЛЮБОГО теста
                      #   одинаково) — firstStepBlock() называет шкалу, вокруг
                      #   которой пишется последний раздел «С чего начать».
                      #   Слой 2 — язык: семейство промптов «style» переписывает
                      #   готовый текст короче и живее, получая список фактов,
                      #   которые обязаны сохраниться (последний раздел с
                      #   единственным действием — один из них). Слой необязателен: нет
                      #   активной версии — клиент получает текст первого слоя.
                      #   mathLayer() — снимок слоя математики (пороги оператора и
                      #   раскладка по ним), сохраняется вместе с интерпретацией:
                      #   PDF и письмо считаются по ТЕМ ЖЕ порогам, что и текст.
                      #   sourceDump() — ВСЁ, что уходит в нейросеть, одним текстом
                      #   (промпты обоих слоёв + сообщение с расчётом) для кнопки
                      #   «Скопировать промпт и данные»; ничего не отправляет.
                      #   MANUAL_MODEL — пометка отчёта, полученного в чужом чате
                      #   и вставленного руками (модель сервису неизвестна)
    report.php        # Брендированный отчёт (Verdana) → HTML/PDF/письмо: диаграмма,
                      #   матрица, итоги методики; таблиц нет. Текст интерпретации
                      #   всегда начинается с НОВОЙ страницы. Плюс разбивка текста на
                      #   блоки Markdown для правки абзацев до выгрузки в PDF
    trash.php         # КОРЗИНА: удаление анализа и интерпретации — мягкое
                      #   (deleted_at). Месяц (Trash::KEEP_DAYS) лежит в «Удалённых»,
                      #   откуда возвращается одним кликом, потом исчезает само;
                      #   можно и вручную. Анализ уносит и возвращает свои
                      #   интерпретации целиком. Все списки читают deleted_at IS NULL
    mailer.php        # SMTP-отправка
    settings_store.php# key/value стор настроек
```

### Поток данных (happy path)

1. **Ingest.** Загрузка/вставка Excel → `Profile::fromFile()` извлекает метаданные,
   тип теста (по строке «Методика») и когнитивные баллы.
   Папка‑watcher (`bin/watch.php`) делает то же автоматически при появлении файла.
2. **Скриншот.** Оператор вставляет (Ctrl+V) скриншот таблицы значимости →
   `LLM::recognizeSignificance()` (vision-модель читает график) → `Phys::fromVision()`
   выравнивает «Знач.» по осям; запасной путь — `LLM::ocrImage()` + `Phys::parse()`.
   Из чисел скриншота берётся ТОЛЬКО столбец «Знач.»: «Балл», «m» и прочие
   игнорируются, баллы теста приходят из Excel.
3. **Расчёт и картинки.** `Metrics::build()` считает всё (уровни, физиологию,
   разделы, итоги, координаты матрицы); `Chart::svg()` строит паутинку и
   накладывает физиологию на когницию, `Matrix::svg()` — матрицу «когниция ×
   эмоция». Оператор сверяет расчёт в таблице на странице результата и при
   необходимости правит «Знач.», флажок достоверности и **СМК** (столбец
   правится руками: распознавание теряет его чаще всего, а соотношение X/Y/Z
   нужно независимо от достоверности). Пороги уровней и контраст размеров
   кружков он двигает прямо на матрице — они общие для сервиса и сохраняются.
4. **Интерпретация — ДВА СЛОЯ.** Вместе с расчётом уходит и **опора первого
   шага** (`Metrics::firstStep()`): шкала с самым достоверным телесным откликом
   и наибольшим весом — вокруг неё отчёт заканчивается одним конкретным
   действием. Выбор шкалы делает код, нейросеть только пишет сам шаг.
   По типу теста выбирается активная версия
   промпта; `Interpret::run()` отдаёт нейросети готовый расчёт (без сырых данных),
   а затем прогоняет полученный текст через второй слой — промпт «style»,
   который правит язык, не трогая факты. Вместе с текстом сохраняются обе версии
   промпта и снимок слоя математики (`Interpret::mathLayer()`): пороги, которые
   оператор выставил к этому моменту, и раскладка по ним — чтобы PDF и письмо
   считались по тем же правилам, что и текст. Ту же связку промптов и данных
   можно просто **скопировать** кнопкой рядом (`?p=interp_source` →
   `Interpret::sourceDump()`) — запрос к нейросети при этом не уходит. Кнопка
   сразу открывает **окно вставки готового отчёта**: текст, полученный в чужом
   чате, сохраняется той же командой (`?p=interp_paste`) с той же версией
   промпта и тем же снимком слоя математики, но с пометкой модели
   `Interpret::MANUAL_MODEL` — чат, в котором его получили, сервису неизвестен.
5. **Правка.** Один общий редактор на весь текст (`?p=interp_text`): двойной клик
   по тексту на странице результата открывает Markdown с курсором ровно там, где
   кликнули, клик за пределами поля — сохраняет автоматически; карандаш ✏ рядом
   открывает тот же редактор, если кликать не по чему. ↶/↷ в шапке карточки
   листают последние сохранённые правки этой интерпретации (в рамках текущего
   открытия страницы). В базе лежит Markdown, поэтому правка сразу уходит и в
   PDF, и в письмо.
6. **Выдача.** `Report::html()` → брендированный PDF (печать из браузера, Verdana)
   или письмо клиенту (`Mailer`). Таблиц в отчёте клиента нет — вместо них матрица.
7. **Удаление и возврат.** 🗑 не стирает, а помечает (`Trash`): месяц отчёт лежит
   в «Удалённых» (`?p=trash`) и возвращается одним кликом. PDF и письмо по
   удалённой интерпретации не собираются, пока её не восстановят.

### Конвенции кода

- PHP 8.4, `declare(strict_types=1)` в новых файлах, классы — `final`,
  статические фасады (как в существующей библиотеке).
- Комментарии и UI — по-русски (язык команды); идентификаторы — латиницей.
- Совпадай по стилю с окружающим кодом: плотность комментариев, именование.
- Любую новую обработку Excel/диаграммы проверяй на реальных образцах:
  `Sources/Дронов Андрей 19-06-2026 15 02.xls` (эталон: 12 баллов
  9,9,9,8,9,9,7,7,9,8,9,9; методика СМУ) и
  `Sources/Дронов Андрей Басса-Дарки 23-06-2026 13 22.xls` (эталон: 8 баллов
  9,7,7,3,5,8,11,3; тип `bd`; индексы: агрессивности 27 из 34, враждебности
  13 из 18 — оба выше нормы).
