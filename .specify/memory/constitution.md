# NeuroPro Constitution

Принципы проекта психофизиологической интерпретации тестов «Эгоскоп». Конституция
имеет приоритет над прочими практиками; отклонения требуют явного обоснования в
плане фичи (`specs/NNN-*/plan.md`).

## Core Principles

### I. Диаграмма — детерминированная математика
Радар‑диаграмма (паутинка) и любое наложение физиологии на когницию строятся
**только** кодом‑геометрией (`app/lib/chart.php`). Нейросети **запрещено**
использовать для построения, расчёта или «дорисовки» диаграммы. Нейросеть —
исключительно для (а) текстовой интерпретации и (б) OCR скриншота.

### II. Достоверность данных (NON‑NEGOTIABLE)
Числа берутся из Excel‑выгрузки и распознанного OCR‑скриншота. Запрещено
выдумывать, додумывать или подставлять отсутствующие значения. Если данные
неполны — это честно отмечается (прочерк в таблице, оговорка в начале
интерпретации). То же правило зашито в промпты.

### III. Чистый PHP, без Composer
Только стандартные расширения: `ext-curl`, `ext-gd`, `ext-pdo_sqlite`, `ext-zip`,
`ext-dom`, `ext-mbstring`. Переиспользуем существующую библиотеку (`app/lib/`,
исходно — `4neuropro`). Новые зависимости добавляются только при явном
обосновании и одобрении.

### IV. Секреты — вне кода
API‑ключи, пароли, SMTP — только через ENV или таблицу `settings`
(редактируется в `setup.php`, защищён `ADMIN_PASSWORD`). В коде и в Git секретов
нет. `app/data/` (БД, логи, загрузки) — gitignored.

### V. Версионирование промптов и трассируемость
Каждая интерпретация привязана к конкретной версии промпта (модель + текст +
комментарий). История версий не удаляется задним числом: версию промпта можно
удалить **только** если по ней нет ни одной интерпретации. Активная версия
используется в авто‑режиме. Удаление интерпретаций — с подтверждением.

## Технологические ограничения

- PHP 8.4, `strict_types`, `final`‑классы, статические фасады в стиле библиотеки.
- Хранилище — единый файл SQLite (та же БД, что и `settings`).
- Провайдеры нейросетей — OpenRouter и Yandex (выбор и fallback в `llm.php`).
- OCR — Yandex Vision OCR.
- Шрифт клиентского отчёта — **Verdana**; бренд — «НейроПро».
- UI и комментарии — по‑русски; идентификаторы — латиницей.

## Рабочий процесс (Spec‑Driven + BMAD)

- Любая фича начинается со спецификации Spec Kit (`/speckit-specify`), затем
  `/speckit-plan` под эту Конституцию, затем `/speckit-tasks`.
- Реализация — вертикальными BMAD‑историями (`bmad-dev-story`): каждый срез
  рабочий и проверяемый на эталонном образце из `Sources/`.
- Перед PR — `bmad-code-review` и `/speckit-analyze` (согласованность артефактов).
- Подробности маршрутизации методологий — в `CLAUDE.md`.

## Governance

Конституция имеет приоритет над прочими практиками. Изменения фиксируются в этом
файле с обновлением версии и даты. Каждый PR должен соответствовать принципам
I–V; сложность и отклонения — обосновываются в плане фичи.
