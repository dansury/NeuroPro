# NeuroPro — веб‑сервис интерпретации тестов «Эгоскоп»

Загрузка Excel‑выгрузки + скриншот таблицы значимости → математическая
диаграмма‑паутинка (когниция ⊕ физиология) + интерпретация нейросетью →
брендированный PDF (Verdana) / письмо клиенту.

## Структура репозитория

```
www/       # веб-корень сайта — ровно это зеркалится на прод через pull.php
  lib/     # вся библиотека (чистый PHP, без Composer)
  app/     # рабочее приложение анализа (/app/)
bin/       # демон слежения за папкой (watch.php / watch.bat)
data/      # SQLite + логи + загрузки (создаётся сам; в git не попадает)
.env       # секреты — рядом с data/, НАД веб-корнем (см. .env.example)
Sources/   # исходники заказчика: промпты, образцы .xls, лого, референсы
specs/     # Spec Kit: спеки/планы/задачи
```

## Запуск

```bash
php -S 127.0.0.1:8080 -t www
# Лендинг:   http://127.0.0.1:8080/          (кнопка → /app/)
# Анализ:    http://127.0.0.1:8080/app/      (рабочее приложение)
# Настройки: http://127.0.0.1:8080/setup.php (пароль = ADMIN_PASSWORD)

# Слежение за папкой (auto-ingest .xls):
php bin/watch.php 5
# При появлении нового файла демон открывает APP_URL в браузере оператора
# (по умолчанию http://neuropro.skywood.club/app/; пусто — выключено).
```

### Windows (локально)

Демон кроссплатформенный. На Windows удобнее запускать через лаунчер —
он включает UTF-8 в консоли и сам перезапускает демон при сбое:

```bat
rem интервал опроса по умолчанию 5с, можно передать аргументом:
bin\watch.bat 10
```

PHP берётся из `PATH` (`php.exe`) либо из переменной окружения `PHP_BIN`.
Папку наблюдения задайте через `WATCH_DIR` (по умолчанию `data/incoming`).
Для автозапуска при входе в систему добавьте ярлык `watch.bat` в `shell:startup`
или создайте задачу в «Планировщике заданий». Частично записанные/копируемые
файлы демон пропускает, пока их размер не стабилизируется между опросами.

## Конфигурация

Секреты — через `.env` или `setup.php` (`OPENROUTER_API_KEY`, `YANDEX_API_KEY`,
`YANDEX_FOLDER_ID`, SMTP‑параметры, `ADMIN_PASSWORD`, `WATCH_DIR`, `BRAND_*`).

**Нейросеть по умолчанию — Яндекс** (`LLM_PROVIDER=yandex`, модель `yandexgpt`),
поэтому для работы достаточно `YANDEX_API_KEY` + `YANDEX_FOLDER_ID`: тем же
ключом работает и Vision OCR скриншота значимости. OpenRouter подключается
запасным вариантом, если задан `OPENROUTER_API_KEY`.

Если модель не отвечает, `LLM::dispatch()` пробует её же у второго провайдера
(`LLM_PROVIDER_PRIORITY`), затем модели из `LLM_FALLBACK_MODELS`. Слаг модели
никогда не отправляется чужому провайдеру: раньше openrouter‑модель, у которой
провайдер переписывался на Яндекс, уходила как
`gpt://<folder>/google/gemini-2.0-flash-001/latest` и получала
`YANDEX HTTP 400: Failed to get model`. Открытые модели каталога
(`deepseek-*`, `qwen3-*`, `gemma-*`) дают ту же ошибку, если они не подключены
в вашем каталоге Yandex Cloud — первопартийные `yandexgpt` / `yandexgpt-lite`
доступны всегда.

**Куда класть `.env`:** над веб-корнем, рядом с каталогом `data/`
(локально — корень репозитория, на хостинге — каталог над корнем сайта).
Шаблон — `.env.example`; порядок приоритета: настройки в `setup.php` →
переменные окружения процесса → файл `.env` → значения по умолчанию.

Если внешние сервисы не настроены (OCR, нейросети, SMTP), приложение
показывает предупреждение на каждой странице, а любая ошибка вызова сервиса
выводится оператору — молчаливых отказов нет.

## Деплой

Прод обновляется через `https://<host>/pull.php`: в корень сайта зеркалится
**только** содержимое `www/` (см. `pull-config.php`, `subdir = /www`).
Каталог `data/` и `.env` живут над корнем сайта и деплоем не затрагиваются.

## Требования

PHP 8.4+ с расширениями: curl, gd, pdo_sqlite, sqlite3, zip, dom, mbstring.
Composer не требуется.
